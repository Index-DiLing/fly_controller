# 运行期所有权与通信契约

更新日期：2026-10-16。本文描述初始化完成后的代码契约；不包含关中断死循环式致命停止。

## 1. 所有权

- 控制线程独占 SystemState、Mode、Operation、EKF、PID、混控、DShot 和电机定时器。其他线程只能发布输入或请求。
- Sensors 独占采集硬件、解析器与测量参考。BMI088 FIFO、单位和机体系换算、气压高度基准、GNSS ENU 转换均在相应采集线程中完成；控制线程只读样本。
- 链路线程独占无线设备、调度器、解析器、ControlInput 发布副本、请求 ID、急停握手状态和链路统计。
- 日志线程是初始化后唯一的调试串口协议 / TX 缓冲 / DMA / check() owner，也是运行期 flash 日志写入者。
- 初始化阶段允许同步访问外设。bootLogLine 投递信箱后，由启动线程统一成帧并等待 DMA 完成，所有启动模式一致；日志定时器启动后不再调用启动发送入口。旧启动回调在交接前解除绑定，初始应答必须在交接前发送完成。
- 启动异常记录器仅在 initialize 调用期间存在，用于诊断输出，不参与解锁判定。startupReady 反映必需线程/定时器实际创建和启动结果；传感器及电源可用性仍由当前 Health 判断。

FlightShared 是生命周期覆盖所有线程的接线对象，不是可随意读写的状态仓库。
EXCEPTION_HANDLE、logContext 和请求/故障通道绑定指针是启动期设置的非拥有引用，运行期不热切换。

## 2. 通道表

| 方向 | 通道 | 语义 / 背压 |
| --- | --- | --- |
| 链路、后续本地适配层 → 控制 | MPSC<Request> | 默认 16 条；普通请求 FIFO；满时拒绝新请求并返回失败，不覆盖旧请求 |
| 链路 → 控制 | LockedCell<ControlInput> | 最新完整输入；普通操纵、速度、高度、电机值和急停锁存字段分开解释 |
| 控制 → 链路 | SPSC<RequestResult> | 默认 16 条；包含请求 ID、执行结果、原无线序号及操作码；急停使用独立结果类型 |
| IMU → 控制 | SampleStream<ImuSample, 32> | 保序、满时丢新并累计计数；样本序号可发现丢帧，控制每圈最多消费 16 条 |
| 光流 → 控制 | SampleStream<FlowSample, 8> | 增量不可合并成最新值；满时丢新并累计计数，每圈最多消费 4 条 |
| 气压 / 测距 / GNSS / 电源 → 控制 | SampleSlot<T> | LockedCell 保存最新值与发布序号；气压/测距按发布序号去重，GNSS 速度按独立 velocitySequence 去重，不把其他句子的更新当成新速度 |
| 各采集线程 → 控制 | Health 内逐源 LockedCell<HealthState> | 最后成功采样时间、是否曾采样、当前可用；仅该源的采集线程写该项 |
| 链路 → 控制 | 链路上下文的 Health | 只使用 LINK 项；控制本地合成健康视图，不反向写传感器健康项 |
| 各生产者 → 控制 | MPSC<ExceptionCode> + 锁存动作位 | 只进入需要控制关注的故障；队列满仍保留停止输出等动作位，每圈最多取 8 条明细 |
| 各生产者 → 日志 | LogChannel 的文本池 / 异常信箱 | 多生产者短临界区投递；日志线程唯一消费；不由生产者直接拼包发送 |
| 控制 → 日志 | LogQueue | 单生产者/单消费者拓扑，内部使用线程临界区；满时丢最老日志并计数，不是允许生产者越界改队首的无锁 SPSC |
| 控制 → 日志 | DebugQueue | 单生产者/单消费者拓扑，默认 8 条；满时丢最老样本并计数；仅串口调试模式产生（原始观测 + 同刻 EKF 结果，供上位机画融合状况曲线） |
| 控制 → 所有读者 | LockedCell<PublishedFlight> | Snapshot + telemetry 一次整体发布；包含发布时间和序号；读者不可修改控制内部状态 |
| 日志 → 控制 | LockedCell<LogStatus> | 写满、错误、累计写失败数；控制线程不直接读取日志线程的 flash 写入状态 |
| 链路 → 日志 | LockedCell<LinkStatistics> | 链路 owner 本地更新后整体发布 |
| 控制 → 日志 | LockedCell<PerfStats> | 负载统计独立发布，不保证与 PublishedFlight 属于同一控制圈 |

Health 快照由逐项读取构成，不宣称各传感器同一时刻采样。健康 = 曾有有效样本、当前未报失败、最后成功时间未过期。
设备初始化成功不等于已经有健康样本。失败不会覆盖最后成功时间；所有年龄判断使用无符号毫秒差，支持计时器回绕。
默认新鲜度：IMU 20 ms、光流 100 ms、气压/测距/电源 200 ms、GNSS 2000 ms。仍需结合实机采样周期验证。

### 测量有效性与参考系

- BMP388 返回 NewData / NotReady / Failed。NotReady 不发布、不刷新测量时间和 Health；过期仍按最后成功时间判定，不因一次正常等待就报告故障。
- BaroSample 同时发布绝对/相对气压高度及 referenceSequence。启动与重标均累计 16 个基本有效的新样本，未完成首次参考时 referenceSequence 为 0，不进入高度融合。
- 控制侧只设置 lock-free atomic<bool> 重标请求；请求未完成时合并重复请求。气压线程独占累积和参考状态，发布新参考样本后再清除请求标志。控制消费到新 referenceSequence 时同步重置 EKF 并保留姿态。
- 解锁序列开始时请求气压重标；电机接管前再消费一次最新气压样本。若电机初始化等待结束时仍未完成重标，则停止输出，不带着未完成参考进入控制接管。
- GnssReference 保存首次合格定位建立的会话 ENU 原点，不将其自动解释为每次起飞点。位置有效且原点可用时发布局部位置；水平速度不依赖位置原点，必须同时具备有效、新鲜的地速与航迹角。
- GNSS velocityMs 取速度和航迹角字段中较旧的接收时间，velocitySequence 仅在这两个字段更新时推进。单纯 GGA/其他质量字段更新不得重复融合旧速度。
- 采集层负责基本有效性、物理量和坐标转换；控制/估计层保留消费游标、融合接纳及其时间状态。光流换算仍依赖 EKF 高度/姿态和角速度，留在估计侧，不回读控制状态驱动采集线程。

## 3. 请求和 ACK

Request 保留 Task 词汇，同时携带 source、id、issuedMs、safetyEpoch 和可选无线关联字段。
投递者必须填写当前时间和 control.safetyEpoch，不能把进入队列等同于请求执行成功。
控制线程每圈最多处理 8 条，重新检查时间、安全代际、状态和解锁条件后才执行。
无线普通命令的最终 ACK 来自执行结果；无线适配层为待执行请求预留下行 ACK 空间，满时返回 Busy，不挤掉已接受请求的结果。
结果通道拥塞时，控制保留待发结果并减少新请求消费量；不等待队列腾空。

当前 RequestResult 只接回链路。Local / Console 是后续适配点，不能冒用链路结果队列作为多消费者通道；若需要异步回复，应新增各自的定向结果通道。

普通队列明确拒绝 RequestEStop。ControlInput 中的旧命令字不能用于解锁或切换状态。
停机推进安全代际，使停机之前已排队的 Arm 等请求失效；重新解锁必须提交新请求。Disarm 即使在地面态也建立新的安全代际。

## 4. 可恢复急停

1. 链路线程收到急停，分配非零 ID，并将 emergencyStopPending 与该 ID 写入 ControlInput。
2. 后续普通输入覆盖时仍携带这个待确认 ID，不因下一帧未含急停而释放。
3. 控制线程首先检查新急停 ID，关闭输出、退出操作、清除本地直控值、锁存 hardStop 并推进安全代际。
4. 完成上述动作后，控制经结果 SPSC 返回 EmergencyStop ACK。ACK 拥塞不阻塞停机，待后续重试。
5. 链路只接受与当前待确认 ID 一致的 ACK。旧 ACK、重复 ACK 均不能解除新急停。
6. ACK 只解除链路侧请求保持，不解除控制侧 hardStop。恢复需要通过安全检查的新 Arm 请求。

多次急停可合并为最新待确认 ID，因为停止输出是幂等动作，不要求每个重复命令各执行一次。
链路握手与控制执行状态分别由各自线程持有。没有实现关中断、改寄存器后永久自旋的致命停止。

## 5. 控制周期与失效边界

控制周期默认 2 ms：读取最新输入和健康 → 优先执行急停 → 有界消费 IMU / 观测 → 检查故障与模式降级 → 审核普通请求与状态切换 → 操作目标、PID 与混控 → 整体发布状态 → 投递日志与统计。
定时器信号合并，最多保留一个未消费唤醒，避免超时后无限追赶积压节拍。

- Manual 只接受仍新鲜的电机帧；普通操纵、高度、速度帧不会替电机帧刷新序号或时间。
- Stabilize / AltHold 要求新鲜操纵帧；仅高度更新不能替旧摇杆续命。
- VelHold 可使用新鲜速度帧；旧摇杆过期后不用旧姿态目标。速度目标过期后不继续沿用旧速度。
- 解锁后必须有新电机帧，旧直控缓存不能在重新解锁时恢复输出。
- IMU 过期或样本序号断裂时，非 Manual 输出停止。高度/光流失效按模式退化，依赖高度的操作不会在无有效高度时继续推进。
- 输入失效且仍有姿态/高度条件时进入失效保护降落，否则停止输出。实际降落动力学仍需台架和仿真验证。
- POWER_VOLTAGE_CUT 锁存输出禁止；目前没有运行期清除接口，但线程、日志与中断仍继续运行，并非致命停止路径。
- 线程 / 信号量 / 定时器创建或启动失败进入启动阻断条件；控制节拍不可用时低速继续发布诊断，不在空指针处崩溃，也不允许解锁。
- DShot 更新不再忙等双缓冲同步；串口 DMA 未完成时日志线程不改写在途 TX 缓冲，也不在控制线程等待串口。

控制线程仍融合带时间戳的异步传感器数据，并非严格时间同步的观测器。当前 IMU 时间戳是采集完成时间，不是器件内部逐样本硬件时间戳。

## 6. 本轮明确保留的后续工作

- 无线请求、执行结果、急停 ID 握手和现有各输入帧已接通；尚未调整遥控器空口协议、重发/去重策略及控制参数。
- 启动期串口配置协议保持不变；运行期旧串口命令回调已解除绑定，尚未迁入日志线程的新请求/应答适配器。此时串口可输出日志，但不能据此宣称旧串口台架控制可用。
- 飞行 flash 模式仍只持久化固定长飞行日志；文本/异常信箱没有新增 flash 持久化格式，无串口出口时有界丢弃。需要异常落盘时另定记录格式。
- 需要实机检查各线程栈水位、IMU FIFO 深度与 SPI 超时、500 Hz 最坏执行时间、DMA 交接、拔传感器和断链行为。主机测试不模拟中断并发，也不证明飞行安全。
- 新增运行期参数集中在 app/runtime/app_runtime_limits.hpp，使用普通 constexpr；未新增 cfg:: 配置键。既有配置体系不在本轮全量迁移。
