## 0. 执行摘要

### 0.1 一句话结论

**链路的物理层和帧层是健康的（交叉对拍 161 万项只差 1 个边界值）；真正拖垮链路的是"状态机 + 协议语义 + 观测面"三件事**：
飞控的杆量历史"只在采信后更新"，一次丢帧就可能与遥控器分叉，之后**永久自锁**（本轮实测日志 22:31:48 后持续 57 秒、100% 拒帧、链路永久失聪，就是这条机制）；
TDMA 相位在 OffGrid/遥控器重启后**没有主动重捕获路径**；
而日志/统计在故障时**显示为正常**（`上行丢 0%`、`链路=在线`），现场无法定位。

## 1. 链路现状与机理速查（审计基线）

- **TDMA**：超帧 120ms = 5×24ms；遥控器（主端）占槽 0..3 发上行（33.3Hz），飞控（从端）占槽 4 发下行（8.3Hz）。SEQ 每帧 +1 mod 16；飞控仅在 `seq%4==3` 的主帧后开窗（`windowDelayUs = 24000-16500 = 7500us`，guard 3ms）。
- **从端接收**：8ms tick（`cfg::time::link::kTickMs=8`）排空 UART→帧层自定界（坏帧只前进 1 字节）→`FrameAdmission::admit()`→ 只有 Ok 才 `SchedSlave::onMasterFrame()`→ 按类型写 ControlInput/投递请求。
- **准入门槛（实际装载）**：`minFrameIntervalUs=18000`、`maxSeqGapWhenSynced=4`、`maxStickStepNorm=0.25`（杆 255.75 counts / 油门 511.75）、`maxMotorCount=1999`；`silentSlotsToStop=2`、`goodSlotsToResume=2`。
- **下行轮转**：`d%16==0 → DL_GPS`（GNSS 关时跳过不发）、`d%4==0 → DL_SYS`、`d%2==0 → DL_STATE`、其余 `DL_ATT`；ACK 优先且**不推进**轮转。
- **两端常量**：飞控 `app/control/app_flight_stack.hpp:656-713`；遥控器 `components/rc_core/include/app_config.h:265-292`、`components/fc_link/fc_link.c`。

## 2. 实测日志复盘（`.tmp_analysis/raw.log`，2026-10-17 22:28–22:32，222s）

本轮最有力的现场证据（飞控调试串口，含 kmpFly 上位机时间戳）：

| 时间 | 现象 | 判读 |
|---|---|---|
| 22:29:03–22:29:19 | 收帧 31–34/s、采信拒 0、采纳≈收帧 | 链路正常 |
| 22:29:19–22:31:48 | 间歇出现 **成对 0x0204**；采信拒按 1/2/3…16/18/22 成簇增长；0x0404(BARO) 几乎总与 0x204 同窗 | 短系统停顿/丢帧造成两类拒绝；能自愈 |
| 22:30:53.3–22:30:57.4 | **持续 5s、100% 拒帧**，发帧=0；22:30:58 一帧回落进阈值后自愈 | StickStep 自锁的"短版本"（恢复条件是杆量回到旧值附近） |
| 22:31:48.8–日志结束 | **永久冻结**：收帧仍 33/s、拒(CRC)=0、采信拒增量=收帧增量、采纳卡 5001、发帧卡 1211；0x204 只报一次 | **StickStep 自锁的永久版本** |

不变量（把候选判据压到唯一）：
1. `拒=0` ⇒ 帧是合法编码器产出的（不是噪声/半帧/回声）；
2. 收帧 = 33/s ⇒ 没有积压/补发/空口丢帧（排除"一个 tick 排空多帧"）；
3. 采信拒与收帧 1:1 ⇒ 100% 被 `admit()` 拒绝（不是 sched 的 OffGrid/Duplicate——那两类不进 admitRejects）；
4. 采纳/发帧/跳过GPS 同时冻结 ⇒ 无 admit Ok、无锚点、无窗口；
5. 0x204 只在冻结瞬间报一次 ⇒ 它是 health 边沿事件（`app_health.cpp:55-62`），不是周期事件；
6. 冻结发生在运行 167s，不是 71.6min（微秒回绕）或 25.57s（CYCCNT 回绕）的整数倍 ⇒ 与历史上两个时基元凶无关。

**结论**：这是一次"**空口丢 1 帧（或一次 TooSoon 拒绝）+ 杆量正在变化 ⇒ 两侧杆量历史分叉 ⇒ 杆量停在分叉位置 ⇒ 永久拒帧**"的完整现场。`0x0404` 是气压计读失败，与链路同窗说明存在共同短停顿（链路错过 tick → δ∈(6,18)ms → TooSoon/OffGrid），它是**诱因而非主因**；建议另开一条传感器线排查 I2C 停顿。

> 注意：如果不先补 Phase 0 的 verdict 计数，下一次台架仍只能看到"采信拒在涨"，无法确认是 STICK_STEP 还是 TOO_SOON/OFF_GRID。**先加观测再改逻辑**是本文的第一原则。

## 4. 根因链（0x204 / NO LINK / 永久失聪）

```
[多源诱因]
  空口丢 1 帧 / E220 AUX 忙丢帧 / TooSoon / OffGrid / 帧长变化引起 8ms 跳拍
        │
        ▼
[飞控] 该帧被 admit 拒 → 不更新 m_lastSeq / m_lastRxUs / m_lastRoll…
        │                                   ▲
        │                          （遥控器侧历史已前进）
        ▼
[分叉] 飞控旧杆量 S 与遥控器当前杆量 V 相差 >255（油门 >511）
        │
        ├─ 杆量继续变化/停在分叉位置 ⇒ 之后每一帧都 STICK_STEP（无解毒）
        │
        ▼
[丢槽] 被拒帧不喂 sched ⇒ 连续 2 槽无有效上行 ⇒ missedMasterSlots≥2 ⇒ 静默（只收不发）
        │
        ▼
[0x204] health 边沿报 1~2 条（0x205 永不出现）；下行窗口不再开
        │
        ▼
[RC] 500ms 无下行 ⇒ LINK 超时 / NO LINK；飞控 2s 无新输入 ⇒ 失效保护/停输出
        │
        ▼
[不可恢复] 只要杆量不回到 S±255，或相位 OffGrid 不重锚 ⇒ 只能重启两端
```

**三条独立触发链**（整改时要分别闭合）：
1. **杆量历史链**（FC-01）：丢帧/拒绝 → 分叉 → 自锁；
2. **相位链**（FC-02）：遥控器重启/相位跳变/8ms 跳拍 → OffGrid → 不重锚 → 窗口永不开；
3. **时序/物理链**（FC-04/PHY-01）：窗口余量为负 → 下行撞槽 0 → 上行丢帧 → 反馈到链 1。

## 5. 整改计划（四阶段，按依赖排序）

> 原则：**先观测 → 再止血 → 再加固 → 最后动协议**。每个阶段都能独立上台架验收、独立回滚；不把"协议升级"和"止血"混在一次烧录里。

### Phase 0：观测补齐（0.5–1 人日，FC + RC，零行为风险）

**目标**：下一次台架必须能回答"这一帧被哪条判据拒的、差多少"。

FC（只加统计/日志）：
1. `LinkStatistics` 增 `admitRejBy[AdmitVerdict::Count]`；在 `linkHandleUpFrame()` 的拒绝分支按 verdict 累加（`FrameAdmission::rejectCount()` 已现成，`dlx_link_sched.hpp:1067`）。
2. `[Link]` 行追加：`拒因=STICK_STEP=x TOO_SOON=y SEQ_JUMP=z OFF_GRID=…`、`ACK丢弃`、`GPS跳过`、`静默期命令丢弃`、`窗口获得/实发`。
3. 最后 N 帧环（8~16 条）：`{verdict, seq, roll/pitch/yaw/thr, parseUs, 上帧采信时刻}`，0x204 边沿与 `[Stat]` 按需打印。
4. sched 计数：`offGrid/duplicate/timeBackwards/desync/resync` 发布到 `[Link]`（现在全在 sched 里不落日志）。
5. `ulLoss/dlLoss` 改滑动窗口（最近 32 窗）+ GPS 跳过单列 + 启动 <16 窗置 0。
6. 统计 `rt_sem_take` 返回时刻与 8ms tick 的偏差、循环耗时（定位偶发 0x404 同窗的系统停顿）。

RC：
1. `f` 行增加 rtt 直方图（P50/P95/max）、`tx_busy`、`ack_drop`、`dl_bad/dl_lost` 分布；屏幕日志同源打印。
2. 把本轮自建的**两端交叉对拍 harness** 落到 `test/link_check/run_cross.ps1` + `check_timing_params.py`（161 万项 <1s，可进 CI）。

**验收**：台架 30min，能按判读表（§6.4）区分是 STICK_STEP / OFF_GRID / TOO_SOON / RF 丢帧。

### Phase 1：飞控止血（2–4 人日，仅 FC，wire 不变）

| # | 改动 | 要点 / 风险 |
|---|---|---|
| S1 | **StickStep 改为"夹取并采信"**：不整帧拒；把值夹到 `last ± 0.25` 后采信并更新历史 | 保留防噪能力、消除自锁；单帧仍不会跳变；回滚=开关。**这是本轮最高优先级的代码改动** |
| S2 | **静默后允许重捕获/清杆量历史**：`muted` 锁存后（或连续拒绝 ≥N=6 帧），允许下一帧按"首次捕获"重锚；`muted>300ms` 时清 `m_haveStick` | 只清相位/杆量，不清 SEQ 窗口（防重放）；抖动场景最多多放行一帧 |
| S3 | **窗口关闭加 guard**：`windowClose = min(open+slot, 下一主端帧预计发射 − guard)` | 防止下行压到槽 0；需 sched 知道 expectedGap |
| S4 | **网格容差 ≥ 一个 tick**（6→10ms）作为时间戳改造前的过渡；或直接做 Phase 3 的到达时间戳 | 6<8 是数值不自洽；改 10ms 风险=漏判 1 个槽，可接受 |
| S5 | **GNSS 关闭时禁用 GPS 槽**：`gpsEvery=0` 表示禁用；`downlinkParamsValid` 允许 0；装载处用 `kGnss ? kDlGpsEvery : 0` | 修完两端 6.25% 假丢包归零，SYS 回 480ms；RC 无需改 |
| S6 | **ACK 修正**：容量算式拆开（只按 pendingAck 判满）；连续 ACK 限 2 窗；E-Stop 补 DL_ACK；`ackDropped` 上报 | 避免 3–4 ACK 把 ATT/STATE 推过 RC 阈值；E-Stop 现在没有任何回执 |
| S7 | **failsafe 接线**：control 线程把真实 `fsLvl/fsRsn` 放进 `PublishedFlight`，链路线程填 `s.failsafeLvl/Rsn`；编码器夹到 4/8 | 只发布真实存在的 NONE/HOVER_LAND/CUT；不改 wire |
| S8 | **静默期命令白名单**：muted 时只放行 DISARM/EStop/PING，其余丢弃且不刷新 `receivedMs` | 默认关，台架验证后打开；修 FC-05 |
| S9 | 启动 health 初始化补一行；0x205 边沿分离（独立 `linkWasOk` 标志） | 只影响提示，无控制影响 |
| S10 | `onSlotGrid` 补 `k == gap-1` 校验；记录 `onMasterFrame` 返回值用于统计 | 防"晚到一槽但 SEQ 连续"把锚点拖后 24ms |

**验收**：① 快速推满杆回中 ×20（拆桨）不再出现 STICK_STEP 增长/0x204；② 人为丢帧/TooSoon 注入后 ≤N 帧自愈；③ 重启遥控器（飞控不重启）后能重捕（配合 Phase 2 的 PING/相位扫描）；④ 30min 台架 0x204=0。

### Phase 2：遥控器加固（1–2 人日，仅 RC）

| # | 改动 | 要点 |
|---|---|---|
| R1 | `wait_slot`：迟到 >1.5 槽（36ms）就重对齐、不补拍（阈值从 1 超帧收紧） | 消除运行期 4–5 帧连发/TooSoon |
| R2 | **NO LINK 恢复流程**：连续 NO LINK >1s 且上行在发 ⇒ 连发 4×`UP_CMD.PING`（第 4 帧 `seq%4==3` 可开窗）；仍无下行 ⇒ 相位平移 12ms 重试（最多 2 次） | 24ms 内任意相位，`{0,12ms}` 必有一个落在 ±6ms 容差内，可绕开 49% 死链（只救相位，不救杆量历史） |
| R3 | DISARM/ESTOP 优先级：队满时覆盖队尾；`main.c` 对 DISARM 失败重试 1–2 次 | 安全方向 |
| R4 | ACK 待配对加 200ms 过期；DL_STATE 丢包准入改看线上原始位（或删掉不可达检查） | 消除误配/死检查 |
| R5 | 阈值 `FC_DL_TIMEOUT 500→600`、`FC_STATE_STALE 700→900`；UI 增加 "LAST KNOWN" 提示 | 覆盖 ACK 挤压 |
| R6 | **摇杆 ADC 失败防护**：记录失败样本数，失败时保持上一有效值并置故障标志；**绝不把 raw=0 当 -1.0 发出** | 修 RC-02；同时上报屏幕日志 |
| R7 | 链路质量差时把 UP_CTRL 单帧步长 255→127（可容忍 1 帧丢失） | 代价：满杆 216ms；建议自适应（丢包率/静默时启用） |
| R8 | 文档/文案修正：满行程帧数、AUX 16.5ms 判读、上电顺序（遥控器先→飞控后；任一端重启后两端同时重启）、优先级数字 | 防止现场按错值操作 |

**验收**：① 单端 `f`：超帧在涨、上行失败≈0、超时槽不持续增长、AUX 低占比 65–70%；② 接飞控后 30min 无 0x204；③ 遥控器重启（飞控不重启）一次，PING+相位扫描能把下行拉回；④ 两键重叠 LOCK 回读必为 DIS。

### Phase 3：结构与协议（1–2 周，BOTH，向后兼容）

| # | 改动 | 说明 / 上线顺序 |
|---|---|---|
| P1 | **到达时间戳**：RXNE ISR 用 DWT 记每字节时刻（最小方案 ~30 行），帧尾时刻作 anchor；或复用 `USARTDmaReceiver`×IDLE（GNSS 已在用） | 根治 Q 0–8ms 与 3–7min 相位跳变；之后把 `kMasterFrameLatencyUs` 标定到实测 L_up（≤21000），**两端同时改** |
| P2 | **准入与调度解耦（仅统计）**：被拒帧单独计"槽到了但不可信"，不锚定、不改 muted；`[Link]` 分列 RF 丢帧 vs 准入拒绝 | 不削弱静默保护 |
| P3 | **DL_CAP 能力帧（TYPE=0x6，≤10B）**：版本/帧表代/sessionId/capBits/支持的 op/ack 容量/各帧节拍；放原 GPS 空窗（d%16==0，≈0.52Hz） | **先升 RC（认 0x6，旧 FC 不发即可）→ 再升 FC**；不要用 DL_STATE 保留位（旧 RC 会整帧拒收，已实测） |
| P4 | **会话/复位语义**：`UP_CTRL.flags` 用 1 位会话奇偶（重启翻转）或新增 `UP_CMD.SessionStart`；飞控收到翻转即清 SEQ/杆量历史；新增无线复位 op（需能力位协商，限速 1 次/s） | 解决"遥控器重启必须双端重启"；旧固件遇新 op 会当未知 op 拒帧，所以必须协商后再发 |
| P5 | **E220 身份**：两端写非零 ADDR/KEY（同套设备唯一），可选 session id | 写错=静默丢包，且 KEY 不可回读 ⇒ 必须两端同时改+回读核对+重启；**飞行前不要临时改** |
| P6 | **FC 下行 TX 改中断/DMA**；`kAuxGate` 接线（真 AUX 发送闸门） | 防裂包；注意不要用临界区包 3.5ms（会打穿 500Hz 控制环） |
| P7 | **帧长/槽长决策**（依赖 21ms 裁定）：缩 DL_GPS 20B→16B，或槽 24→32ms（32 是 8ms 整数倍，仍 4 上 1 下；代价上行 33→31Hz） | 若 21ms 是稳态，24ms 槽装不下 12B+ 下行 |
| P8 | 恢复 `test/link_check` + `test/sched_check` 主机测试；CI 跑交叉对拍 | 注释里承诺的测试实际不存在 |

**兼容矩阵（务必按序）**：
- DL_CAP：RC 先 → FC 后；旧 RC 遇 0x6 会丢 1 字节重同步，只多几个 `dl_bad`，不破坏其它帧。
- 时间戳/容差/窗口参数：FC 先改，RC 常量同步重编译（只影响日志/对拍）。
- 会话位/复位 op：必须两端一起；先协商能力再启用。
- E220 地址/KEY：两端同时；确认前后都要能回读（KEY 不可读，只能靠链路通断确认）。

## 7. 待决问题（需要你拍板）

1. **21ms 是冷启动还是稳态？** 若为稳态，24ms 槽装不下 12B 以上下行帧，必须缩帧或改 32ms 槽（Phase 3 P7）。建议先按 §6.2-3 测，不猜。
2. **是否接受"任一端重启后两端同时重启"作为近期操作规程？** 若接受，FC-02 的相位重捕获可降到 P1；若不接受，S2+P4 必须做。
3. **是否引入 DL_CAP（新帧 0x6）？** 这是解决版本/能力/会话/节拍/复位 op 的最小代价方案；需要 RC 先升级。
4. **E220 地址/KEY 何时改？** 建议台架期完成（两端同时、写后回读+重启验证），飞行前不要临时改。
5. **T22S 与 T30S 是否混用？** 需遥控器侧 `e` 自检日志（DEVTYPE/FWCODE）确认；若混用，下行预算要按 22dBm 侧算。
6. **故障注入能力**：建议做一个"调试注入"开关（丢帧/强制 TooSoon/强制 OffGrid），用于台架回归；仅调试固件启用，飞行构建裁掉。

### 8.3 不建议的做法（本轮审计中确认会踩坑）

1. **只调大 `kMasterFrameLatencyUs` 而不消除 Q**：均值挪对、方差 ±4–5ms 仍在；且上限硬约束 `L_est ≤ slot − guard = 21ms`。
2. **用 DL_STATE 的 7 个保留位做扩展**：旧遥控器会整帧拒收 DL_STATE（已实测），比新帧更危险。
3. **用临界区包住 3.5ms 的 UART 发送**：会直接打穿 500Hz 控制环；应改 TXE 中断/DMA。
4. **在飞行中切 E220 配置模式/改地址**：模块忙时切换会被忽略，且 KEY 不可回读。
5. **把"准入拒绝"算作 RF 丢包**：会让现场误判为射频问题；必须分列。
6. **只靠"两端同时重启"长期运行**：它是近期操作规程，不是修复；S2/P4 仍应落地。
7. **在没加 Phase 0 观测的情况下继续凭日志猜判据**：本轮已经证明 `ulLoss`/`在线`/`采纳` 在自锁时全都"看起来正常"。
