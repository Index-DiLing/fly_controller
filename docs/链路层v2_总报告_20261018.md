## 1. 这轮做了什么

**把链路层从"绝对时间 TDMA"换成"帧计数轮次 TDD"**（用户批准的破坏性更新）：

| 项 | v1 | v2 |
|---|---|---|
| 同步 | RC 本地 120ms 超帧网格 + FC 到达锚点 + 7.5ms 窗口 | 上行帧 `SEQ&3` 就是轮内位置；**时间只用来算 D0 何时发** |
| 帧层 | 1B 头 + CRC-8 | 1B 头 + **CRC-16/CCITT-FALSE（低字节在前）** |
| 类型 | 0x1–0x5 / 0x8–0xD | 不重排；**新增 0x6 UP_ROUND、0x7 HELLO**；UP_CMD 6B(cmd_id)、DL_ACK 5B(cmd_id) |
| 握手 | 无 | **双向同型 HELLO**：4bit 版本 + caps + nonce 回显；版本不一致 MISMATCH、不控制 |
| 轮次 | 120ms，4 上行 + 1 下行 | 120ms，4 上行（22ms 间距）+ 1 下行（U3 末 + guard；U3 丢按 t0 兜底） |
| 唤醒 | 8ms 轮询 | **IDLE/DMA 帧末事件为主**，6ms 定时器只做 watchdog/统计 |
| 失效保护 | 2s 新鲜度 | 不变；DL_STATE 的 failsafe 改为真实值 |

设计口径（冻结）：`LinkAirtimeBaseUs=13555`、`LinkAirtimePerByteUs=387`、`LinkUartByteUs=174`、`LinkRxIdleBytes=1`、`LinkGuardUs=3000`、`LinkDlTimeoutMs=117`、`LinkRoundMs=120`、`LinkFrameSpacingMs=22`、版本=2。两端常量头 **18 个同名同值**，由 `tools/check_link_config.py` 校验。

## 4. 上板发现与修复（重要）

1. **飞控启动卡死**（日志停在 `启动 DMA+IDLE 接收`）：
   `USARTDmaReceiver::start()` 先开 IDLE/NVIC、后装回调；E220 AT 应答留下的 IDLE 挂起使 NVIC 一开就反复进中断，而分发器没有 handler、不读 DR，标志永不清 → 中断风暴。
   **修复**：`start()` 改为“装回调 → 读 SR/DR 清 IDLE → 开 IDLE/NVIC”；app 先 `setHandler` 再 `start`。之后启动/链路正常。
2. **t0 锚点偏差**：E220 整帧收完才吐 UART，`airEnd = rawIdle − (n+1)×174`；此前只减常数 174，t0 偏大 ~1.9ms，兜底 21B 余量只剩 ~0.7ms。**修复**：按帧长修正（`rxIdleBytes`），灵敏度测试（还原旧模型）49 项失败证明回归有效。
3. **下行预算**补上“对端串口排空时间 + 1ms 余量”；迟到容差 12ms→3ms；新增“本轮关闭”；命令超时改日历 600ms（计划书 §13 E11–E15）。
4. **台架口径**：`round` 增加 ASCII 过滤与 `txtSkip`、`ver`、PATTERN `dur=` 自停、`d0AuxUs`、stat min 修正（台架文档已同步）。
