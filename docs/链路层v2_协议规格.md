# 链路层 v2 协议规格（实施用权威口径）

> 状态：2026-10-18 开工版 · 与 [实施计划书](链路层v2_实施计划书.md) 配套。
> 本文是**帧级/状态机级唯一口径**：飞控端 `DL_LIB/link/` 与遥控器端 `components/fc_link/` 都按本文实现。
> 计划书管范围、节奏、验收；两者冲突时，帧格式/时序公式以本文为准，范围/验收以计划书为准。

---

## 0. 一句话

轮次 120ms = 上行 4 帧（22ms 间距）+ 下行 1 帧；上行帧头 `SEQ&3` 就是轮次内位置；飞控在 U3 末字节 + guard 后发 1 帧下行（U3 丢则按 t0 推算超时）；两端用双向 HELLO 交换 4bit 版本，版本不一致不控制。

---

## 1. 物理与帧格式

| 项 | 值 |
|---|---|
| 模块 | E220-400T30S 透传，57600 8N1，信道 23，空速 62.5kbps，32B 分包 |
| 单帧 | ≤21B，**一次连续写完**（中间停顿 >0.5ms 会裂包）；不使用 >21B 的帧 |
| 半双工 | 一次只有一端发；切换由轮次协议保证 |
| UART 字节时间 | 10bit/字节 @57600 ≈ **173.6us/字节**（计算用 174us） |
| 帧成本模型 | `F(n) = LinkAirtimeBaseUs + LinkAirtimePerByteUs·n` = `13555 + 387·n` us（**2026-10-18 P0 台架实测冻结**：F(8)=16509、F(32)=25365；62.5kbps 是射频配置值，有效吞吐仅 ~20.7kbps，差值来自每包固定的前导/编码开销，不是配置错误） |

### 1.1 帧结构

```
B0        = (TYPE << 4) | (SEQ & 0x0F)
B1..      = payload，LSB-first 位打包（先列出的字段在低位，可跨字节，小端）
BN-2,BN-1 = CRC-16/CCITT-FALSE，**低字节在前**（BN-2 = crc & 0xFF）
```

- CRC 参数：poly `0x1021`，init `0xFFFF`，refin/refout=false，xorout=`0x0000`。
- 校验值：`"123456789"` → `0x29B1`。
- CRC 覆盖 B0 .. CRC 前一字节。
- 帧长由 TYPE 唯一决定；坏帧/未知类型只前进 **1 字节**重同步。
- **未在本文件列出位布局的帧（0x1–0x4、0x8、0xA–0xD）与 v1 逐位一致**，只多 1B CRC（总长 +1）。

### 1.2 帧类型表 v2

| TYPE | 名称 | 方向 | 整帧 | 负载 | 备注 |
|---|---|---|---|---|---|
| 0x1 | DL_ATT | ↓ | 13B | 10B | 布局同 v1 |
| 0x2 | DL_SYS | ↓ | 15B | 12B | 布局同 v1 |
| 0x3 | DL_GPS | ↓ | 21B | 18B | 布局同 v1 |
| 0x4 | DL_STATE | ↓ | 10B | 7B | 布局同 v1，仅空 7 位改用途（§3.5） |
| 0x5 | DL_ACK | ↓ | 5B | 2B | **改**：`cmd_id + result`（§3.4） |
| 0x6 | UP_ROUND | ↑ | 11B | 8B | **新**：U0，杆量+session+flags8（§3.1） |
| 0x7 | HELLO | ↕ | 5B | 2B | **新**：双向同型，版本握手（§3.2） |
| 0x8 | UP_CTRL | ↑ | 9B | 6B | 布局同 v1，flags 语义改（§3.6） |
| 0x9 | UP_CMD | ↑ | 6B | 3B | **改**：`cmd_id + op + arg`（§3.3） |
| 0xA | UP_VEL | ↑ | 6B | 3B | 布局同 v1 |
| 0xB | UP_POS | ↑ | 7B | 4B | 保留未用 |
| 0xC | UP_SETPOINT | ↑ | 6B | 3B | 布局同 v1 |
| 0xD | UP_MOTOR | ↑ | 9B | 6B | 布局同 v1 |
| 0xE/0xF | 保留 | — | — | — | 解析为非法类型 |

> 所有"布局同 v1"的帧：位宽/位偏移/定点换算全部沿用现有 `dlx_link_frame.hpp` 与 `fc_frame.c`，不得顺手改。

### 1.3 SEQ 规则

| 帧 | SEQ 规则 |
|---|---|
| 上行 U0–U3 | `seq = (roundCount*4 + pos) & 0xFF`；`pos = 0..3` 与发送位置严格一致；跳过的帧**不占用 seq** 的对应位置（例如本轮跳过 U2，U3 仍用 pos=3 的 seq） |
| 上行 HELLO | 独立 `helloSeq++`；**不参与** `SEQ&3` 位置判定 |
| 下行全部帧 | 独立 `dlSeq++`（含 HELLO 应答）；仅用于丢包统计，没有位置含义 |

- 飞控只按 `seq&3` 给 0x6/0x8–0xD 定位；HELLO 不看位置。
- 遥控器重启后 `roundCount`、`helloSeq` 从 0 开始（session 变化会让飞控清历史）。

## 2. 轮次时序

### 2.1 时间轴（s=22ms）

```
t(ms)  0        22       44       66       ~86(D0 最早)   ~89(仅超时路径)   117        120
       U0       U1       U2       U3       D0(正常)      D0(兜底)          RC 判 DL 丢  下一轮 U0
```

| 事件 | 时刻 |
|---|---|
| U0 发送 | t0（= 本轮锚点，遥控器本地时间） |
| U1/U2/U3 | t0+22/44/66 |
| U3 空中结束（期望） | `t0 + 3·22ms + F(UP_CTRL)` = t0+83038us（F(9)=17038，实测模型） |
| 飞控正常发 D0 | U3 空中结束 + `LinkGuardUs` = t0+86038us |
| 飞控兜底发 D0 | `t0 + 3·22ms + F(UP_CTRL) + LinkU3JitterUs + LinkGuardUs` = t0+89038us |
| D0 最大空中结束 | 110.72ms（21B，兜底路径） |
| 遥控器收完整帧 | 空中结束 + 帧长×174：正常 21B=111.37ms，兜底 21B=114.37ms（均 ≤117ms） |
| 遥控器 DL 超时 | t0+117ms；到点无任何合法下行 = 本轮 DL 丢失 |
| 下一轮 | t0+120ms（本地定时；丢帧不追赶） |

### 2.2 t0 反推（飞控）

收到任意合法上行帧即可反推本轮 t0（不要求收到 U0）。**关键是先把 IDLE 戳换算成"空中结束"**：

```
airEndUs = rawIdleUs - (frameBytes + LinkRxIdleBytes) * LinkUartByteUs
t0Us     = airEndUs - (pos*LinkFrameSpacingMs*1000 + airtimeUs(type))
airtimeUs(type) = LinkAirtimeBaseUs + LinkAirtimePerByteUs * frameLenBytes(type)
```

- **2026-10-18 P0 实测**：模块把整帧**收完才开始吐 UART**（8B 帧首字节 = AUX 下降沿 + 16683us ≈ 空中 16509 + 174），
  帧末 IDLE ≈ 空中结束 + 帧长×174 + 174。所以修正量是 `(n+1)×LinkUartByteUs`，**不是常数 174**：
  少减 `n×174` 会让 t0 偏大 1.9ms（11B 帧），兜底路径 21B 的余量会从 2.6ms 掉到 ~0.7ms。
- `rawIdleUs` = 飞控 USART IDLE 回调入口的 DWT 微秒时刻；`LinkRxIdleBytes=1` 是 IDLE 判定多等的那个字符。
- 每收到一帧都刷新 t0、并记该位置已收；`pos==3` 时记 `u3EndUs = airEndUs`。
- 一旦 `pos==3` 收到，D0 的"最早发送时刻"改为 `u3EndUs + LinkGuardUs`（正常路径，不等兜底）。
- 兜底时刻 `u3DeadlineUs + LinkGuardUs` 仅在**本轮未收到 pos3** 时使用。

### 2.3 D0 发送前检查（每条都必须）

1. **AUX 忙则不发**：发前读 E220 AUX；模块仍忙（AUX 低）→ 放弃本轮 D0（记一次 skip），绝不等待压过下一轮。
2. **预算检查**：`nowUs + airtimeUs(所选下行类型) + 帧长×LinkUartByteUs + LinkDlBudgetSlackUs > t0Us + LinkDlTimeoutMs*1000` → 放弃本轮 D0。只保证"空中结束进窗"不够：遥控器要把**整帧串口收完**才算收到，13B 还要 ~2.3ms、21B ~3.7ms 排空；再加 1ms 调度余量。
3. 一帧一次连续写（DMA 或中断发送），写好立刻置"本轮已发"，**每轮最多 1 帧**。
4. 下行帧不重发；D0 丢失由遥控器计 DL 丢失，下一轮再来。

## 3. 逐帧位布局（新增/修改）

> 位偏移一律相对负载首字节（B1）。LSB-first：先列出的字段占低位。有符号量用 **补码**。

### 3.1 UP_ROUND（0x6，负载 8B = 64bit）

| bit | 宽 | 字段 | 含义 |
|---|---|---|---|
| 0 | 11 | roll | int11 补码，±1023 |
| 11 | 11 | pitch | int11 补码，±1023 |
| 22 | 11 | yaw | int11 补码，±1023（yaw 无效时填 0） |
| 33 | 11 | thr | u11，0..2047 |
| 44 | 4 | flags | 同 UP_CTRL flags（§3.6），bit0=ESTOP |
| 48 | 8 | session | 遥控器本次启动随机 1..255（0 保留不用） |
| 56 | 8 | flags8 | bit0=ESTOP（与 flags.bit0 同值，冗余）、bit1=yaw 有效、bit2=请求 DL_GPS、bit3..7=0 |

- U0 每轮必发；它同时是"轮次开始 + 最新杆量 + session"三合一。
- 飞控用它判 session 变化并进 RUN；U0 携带的杆量与 U1–U3 同量纲，可单独维持控制。

### 3.2 HELLO（0x7，负载 2B = 16bit，双向同型）

| bit | 宽 | 字段 | 含义 |
|---|---|---|---|
| 0 | 4 | ver | 协议版本，v2 = `2`；`0` 保留 |
| 4 | 4 | caps | 能力位：bit0=GNSS/GPS 相关（RC：想看 DL_GPS；FC：GNSS 已开）、bit1=支持制导帧、bit2=支持 cmd_id/ACK、bit3=0 |
| 8 | 8 | nonce | 请求方随机；应答方**原样回显** |

- 应答帧：`ver` = 本端版本（不因对端版本改），`caps` = 本端能力，`nonce` = 收到的 nonce。
- 同一 TYPE 双向；请求/应答靠"谁发起"区分（飞控不在 ACQUIRE 外主动发 HELLO）。
- HELLO 只用于握手/探测/恢复，**不参与**正常下行轮转，不做遥测。

### 3.3 UP_CMD（0x9，负载 3B = 24bit）

| bit | 宽 | 字段 | 含义 |
|---|---|---|---|
| 0 | 8 | cmd_id | 遥控器分配，1..255 循环，0=无效 |
| 8 | 8 | op | 命令号（同 v1 命令表：0x00 Ping、0x01 ARM、0x02 Disarm、0x03 ESTOP、0x10 SetMode、0x20 Takeoff、0x21 Land、0x22 CancelTask…） |
| 16 | 8 | arg | 参数（SetMode 的模式号等；不用则 0） |

- 遥控器同时只保留**一条**待确认命令；未收到对应 ACK 前每轮 U2 重发**同一 cmd_id**；从命令创建起超过 **600ms**（≈5 轮，按日历时间计，不按"实际发出次数"）未确认 → 报失败、放弃该条。
- 飞控按 `(session, cmd_id)` 去重：最近 8 条内重复 → **只重发 ACK，不重复执行**；session 变化清空去重历史。
- 命令执行结果用 DL_ACK 回传。

### 3.4 DL_ACK（0x5，负载 2B）

| bit | 宽 | 字段 |
|---|---|---|
| 0 | 8 | cmd_id（被确认的 UP_CMD.cmd_id） |
| 8 | 8 | result（0=OK，1=BadCommand，… 11=AuthFail；同现有 GroundStatus 数值） |

- 有 ACK 待发时 D0 优先发 ACK；一轮只发一条，多条待发按产生顺序。
- v1 的"SEQ 回显"取消：cmd_id 显式携带。

### 3.5 DL_STATE（0x4，负载 7B）空位定义

沿用 v1 的 49bit 用量；原"空 7 位"（bit49..55）改为：

| bit | 宽 | 含义 |
|---|---|---|
| 49 | 1 | 本轮收到 pos0 |
| 50 | 1 | 本轮收到 pos1 |
| 51 | 1 | 本轮收到 pos2 |
| 52 | 1 | 本轮收到 pos3 |
| 53 | 3 | 保留恒 0 |

### 3.6 flags 语义（UP_CTRL 4bit / UP_ROUND.flags）

| bit | 含义 | 备注 |
|---|---|---|
| 0 | ESTOP | **锁存 flag**：每帧重复发送，直到飞控 hardStop/disarm；飞控收到任一帧该位即锁存 |
| 1 | yaw 场有效 | 当前恒 0（无可靠偏航参考） |
| 2..3 | 保留 0 | 解码端发现非 0 可当坏帧或忽略 |

> v1 的 bit0"请求下行窗口"作废：下行窗口由轮次协议保证。

## 4. 飞控状态机（RoundSlave）

状态：`ACQUIRE` / `RUN`。全部时间用 `uint32_t` 微秒 + 回绕安全比较。

```
ACQUIRE:
  收到 HELLO(任意 ver)          -> 记 helloReplyPending(nonce/caps/ver)；保持 ACQUIRE；回 HELLO
  收到 UP_ROUND(pos0)           -> 校验 session；进 RUN；按 2.2 建本轮
  收到 0x8-0xD / 其他下行型      -> 忽略（不采信、不回复、不控制）
  2.2s 从未收到任何合法帧        -> 保持 ACQUIRE（正常现象，等 RC 发起）

RUN:
  收到 HELLO                    -> helloReplyPending；若本轮无活动则尽快回；否则占用 D0 槽
  收到 UP_ROUND                 -> 新 session? 清 cmd 去重/轮次历史；pos=0；重建本轮；保持 RUN
  收到 UP_CTRL/CMD/VEL/SP/MOTOR -> pos=seq&3；刷新 t0/位置位图；pos==3 则记 u3EndUs
  pollTx:
    - ACQUIRE 且有 helloReplyPending 且 now>=helloEndUs+guard -> 发 HELLO 应答，清 pending
    - RUN 且本轮有活动：
        sendAt = 有 u3EndUs ? u3EndUs+guard : u3DeadlineUs+guard
        now>=sendAt -> 按 §2.3 检查 -> 选帧发（HELLO 应答优先，其次 ACK/GPS/SYS/STATE/ATT）-> 本轮结束
    - RUN 且 now-lastValidEndUs > LinkAcquireMs -> 回 ACQUIRE
```

- 同一轮只发 1 帧下行；发完清本轮 `t0/u3End/u3Deadline/posMask`，等下一轮。
- **本轮关闭**：D0 发出（或跳过）后 `roundClosed=true`。此后反推出的 t0 与已记录 t0 相差 `<60ms` 的迟到帧只更新计数/统计，**不得再触发第二帧 D0**；收到 UP_ROUND 或反推 t0 变化 `>=60ms`（U0 丢了、已进下一轮）才开启新轮。
- `u3DeadlineUs` 在收到本轮任意帧时按 §2.2 重算：`t0 + 3·spacing + F(UP_CTRL) + LinkU3JitterUs`。
- 驱逐/丢弃规则：坏 CRC、未知类型、长度不符 → 不改变状态；session 不同但帧型为 0x8–0xD → 在 ACQUIRE 忽略、在 RUN 只用于轮次定位（不切 session）。
- 版本校验：HELLO 的 ver != LinkProtoVersion → 记 mismatchedVer；**仍回 HELLO**（让对方看到本端版本），但 ACQUIRE 不进 RUN；RUN 中若收到不一致 HELLO → 只应答、不中断现有轮次（正常情况下不会发生，两端同版本）。
- ACQUIRE 只对 UP_ROUND 采信（这就是 v1 RC 不会误控制的保证）。

## 5. 遥控器状态机（RoundMaster）

状态：`HANDSHAKE` / `MISMATCH` / `RUN` / `NO_LINK`。

```
HANDSHAKE:
  每 LinkHelloIntervalMs(60ms) 发 HELLO(ver=2, caps, nonce++)
  收到 HELLO 应答:
      ver==2 -> 版本匹配：t0 = 应答末字节+LinkGuardUs；立即进 RUN（在 t0 发 U0）
      ver!=2 -> MISMATCH（记对端版本；继续每 60ms HELLO）
  连续 LinkHelloMax(5) 次无应答 -> NO_LINK

NO_LINK:
  每 500ms 发 HELLO；收到匹配应答 -> RUN（同上）；收到不匹配 -> MISMATCH
  （NO_LINK 恢复上限 ≈ 500ms + 握手往返，不是"3 轮"；验收时单列）

MISMATCH:
  每 60ms 发 HELLO（便于改烧后自动恢复）；收到匹配应答 -> RUN
  只显示 + 拦截控制命令；绝不发 0x8-0xD

RUN:（每轮）
  t0      发 UP_ROUND（永久携带最新杆量；AUX 忙最多等 2ms，仍失败则以当前时刻为新 t0 顺延整轮）
  t0+22   发 UP_CTRL
  t0+44   待确认命令存在 ? UP_CMD : UP_CTRL
  t0+66   按当前模式：UP_CTRL / UP_VEL / UP_SETPOINT / UP_MOTOR
  t0+66~  WAIT_DL
  t0+117  仍未收到任何合法下行 -> dlLossStreak++；否则 dlLossStreak=0
  t0+120  下一轮 U0（t0 += 120ms）
  dlLossStreak >= LinkDlLossToHandshake(2) -> HANDSHAKE（停发控制帧）

迟到规则：
  某帧目标时刻已过 > LinkGuardUs(3ms) -> 跳过该帧（U0 除外）
  U0 目标时刻已过 > LinkGuardUs -> 以 now 为新 t0 顺延整轮（后续帧随新 t0 移位）
  错过 >1 轮的整轮 -> 直接以 now 为新 t0
  理由：飞控兜底 D0 在"期望 U3 末字节 + 3ms + guard"发出；上行帧迟到超过 3ms 还在空中就会和兜底 D0 争用半双工信道。飞控发前读 AUX 忙则放弃本轮 D0 是最后兜底，但发送端不能依赖对端补救。
```

- RUN 内任何合法下行（0x1–0x5、0x7）都算本轮双向通；HELLO 应答还要校验版本。
- **DL 成功判定窗口 = `[t0, t0+LinkDlTimeoutMs)`**：窗口内收到合法下行 → 本轮成功、streak 清零；窗口之后到达的合法下行仍更新遥测/新鲜度，但**不回溯**改变本轮成功标记（那一轮已按丢失计）。
- 收到 HELLO 应答且 ver 不匹配 → 立即 MISMATCH（下轮起不再发控制）。
- 遥控器**不自动发 ESTOP、不自动切模式**；失联只显示 + 拦截。

### 5.1 遥控器端逐类型新鲜度（本地常量，不进共享头）

| 类型 | 超时 | 用途 |
|---|---|---|
| DL_ATT | 300ms | 姿态曲线/主遥测 |
| DL_STATE | 1s | 链路/状态显示 |
| DL_SYS | 1.5s | 电源/位置 |
| DL_GPS | 3s | GPS 页 |
| 任意下行 | 360ms（LinkDegradeMs） | 链路降级显示；命令门控 |

- 新命令门控：`state==RUN && 版本匹配 && now-lastAnyDl < LinkDegradeMs`；否则拦截 ARM/模式/起降/任务命令。
- ESTOP 不受门控（能发就发，作为锁存 flag 的每帧重复）。

## 6. 下行调度（飞控）

每轮 D0 按优先级选 **1** 帧：

1. `helloReplyPending` → HELLO 应答（替代本轮 D0）；
2. 有未发送的命令结果 → DL_ACK（按产生顺序，一轮一条）；
3. GNSS 开启（FC 侧）且 RC caps.bit0=1 且到期 → DL_GPS；
4. DL_SYS 到期 → SYS；
5. DL_STATE 到期 → STATE；
6. 否则 DL_ATT。

- 到期判定用"发送轮号"：`STATE 每 4 轮、SYS 每 4 轮（偏移 2）、GPS 每 16 轮`；到期才发，没发不推进（ATT 为兜底，每轮都可用）。
- ACK 不占轮次计数；HELLO 应答也不推进任何遥测计数。
- 不做固定轮转；缺省节拍与计划书一致。

## 7. 握手/恢复/混烧

| 场景 | 行为 |
|---|---|
| 正常启动 | RC HANDSHAKE 发 HELLO；FC ACQUIRE 回 HELLO；RC 收到匹配应答 → 在应答末+guard 发 U0；FC 见 UP_ROUND → RUN |
| 遥控器重启 | 新 session + HANDSHAKE；FC 可能在 RUN/Acquire：若本轮空闲立即回 HELLO，否则在 D0 槽回；RC 收到应答后重新从 U0 开始；FC 见新 session 清历史 |
| 飞控重启 | FC ACQUIRE；RC 仍 RUN 会继续发 U0–U3；FC 看到 UP_ROUND 直接进 RUN，**不必重新握手**；RC 若连续 2 轮无下行也会发 HELLO，FC 在 ACQUIRE 回 |
| 两端同时重启 | 同正常启动 |
| 连续 DL 丢失 | RC 第 2 轮失败后进 HANDSHAKE（停发控制）；FC 按 200ms 无上行进 ACQUIRE；HELLO 往返恢复 |
| 版本不一致 | 双方都能看到对端 ver；RC 显示 MISMATCH、不发控制；FC 不进 RUN 或不中断现有轮次；改烧成匹配版本后下一次 HELLO 自动恢复 |
| v2 RC + v1 FC | v1 FC 不认 0x7，不回复；RC 停在 HANDSHAKE/NO_LINK，只发 HELLO，**无控制** |
| v1 RC + v2 FC | v1 RC 不发 HELLO/UP_ROUND；FC 停在 ACQUIRE，不采信 0x8–0xD、不发下行；v1 RC NO LINK |

> 说明：握手/重启瞬间，HELLO 可能与对端上一轮的残余帧同刻（半双工协议固有），靠 60ms HELLO 重发兜底；台架验收"无双发"针对 **RUN 稳态**，握手窗口单列。NO_LINK 恢复上限 ≈ 500ms + 握手往返。

## 8. 语义与观测

### 8.1 session / cmd_id

- session：RC 每次启动随机 1..255。FC 看到 UP_ROUND.session 变化 → 清轮次状态、命令去重表、ACK 队列（未发的结果作废）。
- cmd_id：RC 1..255 循环，0 不用；每条命令分配后重发到 ACK 或超时。
- FC 去重表：最近 8 条 `(session, cmd_id)` 的 result；命中 → 重发 ACK，不执行。

### 8.2 ESTOP

- 任一上行帧 flags.bit0=1 → FC 锁存 hardStop（等价于现有 ESTOP 语义），直到新的 ARM。
- RC 在用户按住/触发 ESTOP 期间每帧置 bit0；看到 disarm/hardStop 后停止。

### 8.3 失效保护

- FC：沿用现有 2s 无新输入逻辑（Armed 且非 Manual 且有垂速则缓降，否则停止输出）；DL_STATE 的 failsafeLvl/failsafeRsn 填**真实值**。
- RC：NO LINK / MISMATCH / 降级 只显示 + 拦截；不自动 ESTOP、不自动切模式。

### 8.4 观测（不齐备不验收）

| 端 | 计数 |
|---|---|
| FC | 每位置收帧数、轮次状态、D0 触发来源（pos3/超时）、D0 发送成功/跳过/失败、session、对端版本、上行丢失窗口、最后拒绝原因、D0 触发时刻偏差(us) |
| RC | 每类型最后到达/年龄、DL 丢失数、HELLO 次数、RTT（U0 发→D0 收）、轮长、ACK 结果、握手状态/版本 |
| 日志 | 1Hz `[Link]` 摘要 + 事件行（session 变化、HELLO、DL 超时、版本不一致、U0 发送失败） |
| UI | 链路状态、RTT、握手/版本、丢包计数（最小改动） |

## 11. P0 台架固件（两个独立 main，不碰主线）

> 目标：把 `F(n)`、空速、AUX 时序、收↔发切换、UART 帧末延迟测出来，写回常量头。**测量期间不接电机**。

### 11.1 飞控端 bench（有 USB 串口日志）

- 位置：`test/bench/`（不加入 EIDE `srcDirs`，不参与主线构建）。
- 构建：`tools/bench/build_fc_bench.ps1` 复用 `build/FLY/compile_commands.json` 的 armclang 参数 + 现有 scatter，替换 `release.cpp` 的 `main` 为本 bench main，产出 axf/hex 供 owner 烧录。
- 串口：USART1 115200 文本命令 + 结果打印；E220 用 USART3 + DMA/中断，**不用 simpleLog**。
- 命令（示例，具体由 bench 实现定稿）：
  - `sweep`：n=1..32 逐长度发帧，打印 `AUX 低电平宽度`、`UART 写耗时`；
  - `tx <n> <count> <gap_ms>`：定长定时发送，测稳态；
  - `rx`：只收，打印每帧首/末字节时间戳、AUX 边沿；
  - `echo <guard_ms>`：收到一帧后等 guard 再回同长帧，测往返/切换；
  - `round`：按 22ms×4 + DL 的准协议节拍跑，测实际轮长/抖动；
  - `stat`：打印统计（min/avg/max/P99）。
- 需要 AUX 输入捕获（EXTI 时间戳）与 USART 帧末时间戳，才能把"空中时间/模块忙闲"与"UART 时间"分开。

### 11.2 遥控器端 bench（无 USB 日志）

- 位置：独立 ESP-IDF 工程 `bench/link_bench/`（`EXTRA_COMPONENT_DIRS` 指回 `components/`，复用 E220 驱动），不进入主工程构建。
- 因不能同时插 USB 和 E220 外供电：**日志经 E220 回传**，由飞控 bench 端打印。帧格式用简单 ASCII 行（`<tag> key=value ...\n`），与测量流量区分开。
- 模式（由飞控经 E220 下发一行命令切换）：`RESPOND`（收到一帧后等 guard 回同长/指定长）、`PATTERN`（每 gap_ms 发 n 字节）、`SILENT`、`STAT`。
- 本地也测：U0 定时抖动（记录每次发送相对计划的偏差，回传统计）、AUX 忙等待时长。
- 屏幕只在必要时显示一行状态（避免依赖 LVGL 版式）。

## 12. 实现边界

- 两端帧层必须能**独立主机编译**（FC: g++ C++11；RC: gcc C11），单测不得依赖硬件。
- 任何"顺手改 v1 位宽/换算"的改动都算协议变更：先改本文 + 计划书，再改代码。
- 本文没写到的行为（例如 UI 版式、控制律参数）不在本期范围。

5. **发送窗口 RX 抑制（实现层，不改变线上）**：本端发 D0/HELLO 的窗口 `[发送起点, 空中结束 + guard + 2ms]` 内，半双工协议保证对端不会发送合法数据；此窗口内收到的字节视为换向/串扰瞬变，直接丢弃并单独计数（`txWinBytes`），不进解析器、不计 `拒`。这是为了把 `拒` 留给真实的解析问题。
