## 0. 审批摘要

| 项 | 结论 |
|---|---|
| 方案 | 帧计数轮次 TDD（Frame-Synchronous Round TDD），替换绝对时间 TDMA |
| 轮次 | 120ms = 4 帧上行（默认 22ms 间距）+ 1 帧下行；上行 33.3Hz、下行 8.33Hz、占空 ~72–75% |
| 同步 | 帧内 SEQ 的 `SEQ mod 4` = 帧位置；不再有相位/网格/锚点/窗口常量 |
| 下行触发 | 收到位置 3 的帧 + guard；丢了按"已知剩余帧数"超时兜底 |
| 唤醒 | **IDLE/DMA 帧末事件为主**；6ms 定时器只做超时/watchdog/统计，不参与下行触发 |
| 握手 | **一个双向 `HELLO` 帧（0x7）**：请求/应答同型，携带 4bit 版本 + caps + nonce；版本一致才进 RUN |
| 恢复 | 飞控 ACQUIRE 只收不发；session 识别遥控器重启；版本不一致显示 MISMATCH、不发控制 |
| 类型 | **不重排**：保留 0x1–0x5 / 0x8–0xD；新增 0x6 UP_ROUND、0x7 HELLO；0xE/0xF 保留 |
| 帧层 | 1B 头 + **CRC-16/CCITT**；`UP_CMD` 6B（负载 3B：cmd_id+op+arg），`DL_ACK` cmd_id+result |
| 常量 | 链路参数集中到新头文件，`constexpr`（FC）/ `enum` 或 `static const`（RC），**不引用 `cfg::`** |
| 安全 | 混烧不作为兼容目标；HELLO 版本握手兜底，混烧/版本不一致时不会误控制 |
| 不做 | 无线批量日志/参数/黑匣子（有线直发；后续 WiFi）、E220 身份、OTA |
| 验收 | 轮长 P99 ≤125ms、下行丢失 <0.5%、重启 ≤3 轮恢复、30min 无不可恢复断链 |

**审批即表示**：接受 §1 协议语义、§2/§3 改造范围、§8 任务拆分、§9 待决项按推荐值执行（或给出修改）。

## 1. 协议规范 v2

### 1.1 物理基线（不改）

| 项 | 值 |
|---|---|
| 模块/模式 | E220-400T30S，透传模式，信道 23，空速 62.5kbps，串口 57600 8N1 |
| 分包 | 32B；单帧 ≤21B（CRC-16 后）；一帧一次连续写完，中间停顿 >0.5ms 会裂包 |
| 半双工 | 射频 TDD；LBT 关闭（访问由轮次协议保证）；UAUX=1 |
| 实测单帧成本 | `F(n) ≈ 13.5 + 0.38·n` ms（含 CRC-16 的帧长：9B=16.9、11B=17.7、13B=18.4、15B=19.2、21B=21.5） |
| 身份 | 本期不写 E220 ADDR/KEY（保持 0；同频干扰风险已知，稳定后再处理） |
| 空速 | 62.5kbps 配置值；P0 必须复测真伪（实测边际 ~21kbps 存疑） |

> 注：`F(n)` 原测量基于 CRC-8 帧长；CRC-16 使每帧 +1B，按 0.38ms/B 外推。P0 必须按新帧长复测。

### 1.2 轮次结构（n=4，m=1，120ms，s=22ms）

```
t(ms)   0         22        44        66       69           ~110         120
        U0        U1        U2        U3       D0           (空闲)        U0(next)
        │         │         │         │        │                            │
遥控器  ROUND     CTRL/CMD  CTRL/CMD  CTRL/CMD  ← 等下行/超时 →             下一轮
飞控              收帧…                收位置3 ──guard──→ 发 1 帧下行
```

| 事件 | 时刻（s=22ms） | 说明 |
|---|---|---|
| U0 `UP_ROUND` | 0 | 11B；CTRL + session + flags（**无 version**）；轮次起点 |
| U1/U2/U3 | 22/44/66ms | 9B `UP_CTRL`；U2 可换 6B `UP_CMD`；U3 可换制导帧 |
| 飞控发 D0 | U3 末字节（82.9ms）+ guard(3ms) ≈ 85.9ms | 13–21B；每轮必发 1 帧（兼作轮次回执/心跳） |
| 遥控器收 D0 | ≤117ms（含串口输出） | 收到即更新遥测；117ms 仍未收到 = 本轮 DL 丢失 |
| 下一轮 | 120ms | 本地定时；丢帧不追赶，最多顺延一轮 |

**时序预算**（口径：U3 末字节 = 3s+16.9；D0 起 = 再加 guard；RC 串口收完 = 空中结束 + 串口时间）：

| s | D0 最大 | D0 空中结束 | RC 串口收完 | 正常余量 | U3 丢失超时路径余量 |
|---|---|---|---|---|---|
| **22ms** | **21B** | 107.4ms | 111.1ms | **~9ms** | **~6ms** |
| 22ms | 13B | 104.3ms | 106.6ms | ~13ms | ~10ms |
| 24ms | 21B | 113.4ms | 117.0ms | ~3ms | ~0ms（不可用） |
| 24ms | 13B | 110.3ms | 112.6ms | ~7ms | ~4ms |

**关键约束**：
- 4 帧上行均匀分布，**不背靠背**（背靠背会出现 ~60ms 杆量空档）。
- **IDLE 是硬要求**：正常路径"U3 末字节 + guard"立即发；U3 丢失按"期望 U3 末字节 + 3ms + guard"发。
- 6ms 定时器只做 watchdog：它若晚于预算，**放弃本轮 D0**（RC 记一次 DL 丢失，下一轮再来），绝不压到下一轮 U0。6ms 定时器 167Hz 唤醒，单次检查很短，CPU 负担可接受。

### 1.3 帧格式（CRC-16）

```
B0        = (TYPE << 4) | (SEQ & 0x0F)
B1..N-3   = payload（LSB-first 位打包，可跨字节，小端）
BN-2..BN-1= CRC-16/CCITT-FALSE（poly 0x1021, init 0xFFFF, 不反射, xorout 0）
```

- 帧长由 TYPE 唯一决定；坏帧只前进 1 字节重同步。
- SEQ 每发一帧 +1；`SEQ mod 4` = 上行轮次位置；下行 SEQ 独立自增，仅作丢包统计。
- CRC-16 比 CRC-8 多 1B，假帧通过率 1/256 → 1/65536。

### 1.4 帧类型表 v2（不重排）

| TYPE | 名称 | 方向 | 整帧 | 负载 | 用途 / 节拍 |
|---|---|---|---|---|---|
| 0x1 | DL_ATT | ↓ | 13B | 10B | 姿态/速度/状态，默认遥测 |
| 0x2 | DL_SYS | ↓ | 15B | 12B | 位置/电源/电机，约 1–2Hz |
| 0x3 | DL_GPS | ↓ | 21B | 18B | GNSS 开启时约 0.5Hz；关闭则永不选 |
| 0x4 | DL_STATE | ↓ | 10B | 7B | 状态机/失效保护/链路质量，约 2Hz；空位作上行接收位图 |
| 0x5 | DL_ACK | ↓ | 5B | 2B | `cmd_id + result`，命令回执，优先发送 |
| **0x6** | **UP_ROUND** | ↑ | **11B** | **8B** | **每轮 U0；CTRL + session + flags（无 version）** |
| **0x7** | **HELLO** | **双向** | **5B** | **2B** | **握手/探测；`ver 4b + caps 4b + nonce 8b`；请求与应答同型** |
| 0x8 | UP_CTRL | ↑ | 9B | 6B | U1–U3；杆量/油门 + 4b 安全 flags |
| 0x9 | UP_CMD | ↑ | **6B** | 3B | `cmd_id + op + arg`；替换 U2；同 cmd_id 重传至 ACK |
| 0xA | UP_VEL | ↑ | 6B | 3B | 定速（U3） |
| 0xB | UP_POS | ↑ | 7B | 4B | 保留未用 |
| 0xC | UP_SETPOINT | ↑ | 6B | 3B | 定高（U3） |
| 0xD | UP_MOTOR | ↑ | 9B | 6B | TEST 四路直控（U3） |
| 0xE/F | 保留 | — | — | — | 未来扩展 |

**HELLO 握手（带版本，双向同型）**：

```
遥控器 → 飞控: HELLO { ver=2, caps, nonce }
飞控 → 遥控器: HELLO { ver=2, caps, nonce=echo }
版本一致 → 遥控器开始发 UP_ROUND/CTRL；飞控收到 UP_ROUND 进 RUN
版本不一致 → 双方显示 MISMATCH，不进入控制；改烧匹配版本后下一次 HELLO 自动恢复
```

| 组合 | 行为 |
|---|---|
| v2 RC + v1 FC | v1 FC 不认 0x7、不回 HELLO ⇒ RC 停在 HANDSHAKE，只发 HELLO，不发任何 0x8–0xD ⇒ 无控制 |
| v1 RC + v2 FC | v1 RC 不发 HELLO ⇒ v2 FC 停在 ACQUIRE，不采信 0x8–0xD、不发下行 ⇒ v1 RC NO LINK |
| v2 RC + v2 FC（同版本） | HELLO 往返 → 进入 RUN |
| v2 RC + v2 FC（版本不同） | 双方回/收 HELLO 后显示 MISMATCH；不发控制；改烧后自动恢复 |
| v1 + v1 | 旧协议，不在本期目标内 |

> HELLO 不是"每帧 version"：`UP_ROUND` 仍然不带 version；版本只在启动/探测时交换一次。混烧/版本不一致时靠帧型和版本号双重兜底。

### 1.5 上行语义

- **U0 每轮必发**：`UP_ROUND` 携带最新杆量（6B）+ `session`(8b) + flags(8b)。**不带 version**。
- **session**：遥控器每次启动随机 8b；飞控看到变化即清轮次/命令去重历史。它只用于识别重启，不是版本号。
- **U1–U3**：默认 `UP_CTRL`；U2 可换 `UP_CMD`；U3 可换 `UP_VEL/UP_SETPOINT/UP_MOTOR`。
- **命令幂等**：`UP_CMD.cmd_id` 由遥控器分配（1–255 循环）；重传同一 cmd_id；飞控按 `(session, cmd_id)` 去重，重复只重发 ACK、不重复执行。
- **ESTOP 是锁存 flag**：U0–U3 的 4b flags 每帧重复（bit0），直到飞控 disarm/hardStop 或连续 N 轮；不是一次性命令。
- **U0 不可丢**：AUX 忙则等少量毫秒；仍失败整轮顺延（以当前时刻为新 t0），不允许跳过 U0 发 U1。
- **U1–U3 可丢**：飞控按位置/超时兜底。

### 1.6 下行语义

- **每轮恰好 1 帧**（m=1），由飞控按优先级/到期选择（不是固定轮换）：
  1. 有命令结果 → `DL_ACK`；
  2. GNSS 开启且到期 → `DL_GPS`；关闭则永不选；
  3. `DL_SYS` 到期 → SYS；
  4. `DL_STATE` 到期 → STATE；
  5. 否则 `DL_ATT`。
- 缺省节拍：STATE 每 4 轮（2.08Hz）、SYS 每 4 轮（错开）、GPS 每 16 轮（若开）；ACK 立即优先。
- 不发的类型不占位、不推进计数；遥控器按每类型最后到达时间各自判超时。
- D0 兼作本轮回执：收到任意合法下行 = 本轮双向通。
- `HELLO` 只作为握手应答，不参与正常下行轮转。

### 1.7 同步、超时与恢复

| 参数 | 值 | 说明 |
|---|---|---|
| 位置 | `SEQ & 3` | 0..3；与时间无关 |
| 飞控 guard | 3ms（待实测，可 3–5ms） | 最后一帧末字节 → 允许发下行 |
| 飞控兜底超时 | 从最后合法帧起 `(3−pos)×22ms + 3ms` | U3 丢失时触发下行；3ms 是 RC 帧距抖动余量 |
| 遥控器等下行 | U0 后 117ms | 超过即本轮 DL 丢失 |
| HELLO 间隔 | 60ms，最多 5 次 | 只由遥控器发起；收到同版本 HELLO 即止 |
| 飞控 ACQUIRE | 上电或 >200ms 无合法帧 | 只收不发；收到 UP_ROUND 才进 RUN；HELLO 随时回 |
| 飞控链路降级 | 360ms（3 轮）无合法上行 | 置健康降级；控制输入按既有 2s 新鲜度 |
| session | U0 的 8b，遥控器每次启动随机 | 变化 ⇒ 清轮次/命令去重历史 |
| 版本 | HELLO 的 4b，当前 v2 | 不一致：双方显示 MISMATCH，不进入控制 |
| 在线标记 | RC 收到匹配版本的 HELLO 前不发控制帧 | 防止混烧误控制 |

**恢复矩阵**：

| 场景 | 行为 |
|---|---|
| 丢 U1/U2 | 飞控按位置继续等 U3；控制少一拍，无失步 |
| 丢 U3 | 飞控按 `(3−pos)×22+3` 超时发下行；D0 最多晚 ~3ms，轮长不变 |
| 丢 U0 | 飞控若已 RUN，用 U1 位置继续；若在 ACQUIRE，等下一轮 U0（≤120ms） |
| 无人接下行 | 遥控器下一轮照常发；2 轮后发 HELLO；不影响上行 |
| 遥控器重启 | 新 session + HANDSHAKE；HELLO 往返后从 U0 重新开始 |
| 飞控重启 | ACQUIRE；HELLO 应答 + 下一轮 U0 入网 |
| 两端同时重启 | 遥控器先 HELLO，飞控 ACQUIRE 应答；随后进入 RUN |
| 版本不一致 | HELLO 交换后显示 MISMATCH；不发控制；改烧后下一次 HELLO 自动恢复 |
| 混烧 v1/v2 | 无 HELLO 往返 ⇒ 无控制、无下行（安全） |

### 1.8 失效保护语义

- **飞控**：沿用现有 2s 无新输入 → Armed 且非 Manual 且有垂速则缓降，否则停止输出；`DL_STATE` 的 failsafe 等级/原因改为真实值（本计划内小改动，不改控制策略）。
- **遥控器**：NO LINK / MISMATCH 时只做显示 + 拦截 ARM/模式/起降/任务命令；**不自动发 ESTOP、不自动切模式**（安全保护交给飞控）。
- **E-STOP**：飞控收到任一帧的 ESTOP flag 即锁存 hardStop，直到新 ARM；遥控器重复发送直到看到 disarm/hardStop。

### 1.9 观测（必须齐备，否则不验收）

- 飞控：每位置收帧计数、轮次状态、下行触发来源（位置 3 / 超时）、下行发送成功/忙/失败、session、版本、上行丢失窗口、最后拒绝原因、DL 触发时刻偏差。
- 遥控器：每类型最后到达/年龄、下行丢失数、HELLO 次数、RTT（U0 发 → D0 收）、轮长、ACK、握手状态/版本。
- 日志：1Hz `[Link]` 摘要；事件行（session 变化、HELLO、下行超时、版本不一致、U0 发送失败）。
- UI：链路状态、RTT、握手/版本、丢包计数（最小改动）。

**状态机（RoundSlave）**：
```
ACQUIRE --(收到同版本 HELLO)--> 回 HELLO（保持 ACQUIRE）
ACQUIRE --(UP_ROUND/pos0)--> RUN
RUN --(pos3)--> TX_PENDING --(guard)--> TX --> RUN
RUN --(兜底超时)--> TX --> RUN
RUN --(>200ms 无帧)--> ACQUIRE
任意 --(HELLO)--> 回 HELLO（版本不一致则保持 ACQUIRE）
```

**RX 要点**：USART IDLE（或 DMA×IDLE）帧末唤醒 + DWT 时间戳；解析/CRC-16/自定界；准入分层 L0 CRC/类型、L1 版本/session、L2 序号去重、L3 语义安全；L3 拒绝只夹取/降级，不影响轮次状态。

**TX 要点**：一帧一次连续写；优先 DMA 发送；发前读 AUX；下行最大 21B，若预算不足则放弃本轮。

**RoundMaster 状态机**：
```
HANDSHAKE: 每 60ms 发 HELLO；收到同版本 HELLO → RUN；版本不一致 → MISMATCH（继续 HELLO）
           5 次无应答 → NO_LINK（继续每 500ms 试）
RUN: t0 发 U0；t0+22 U1；+44 U2；+66 U3 → WAIT_DL
WAIT_DL: 收到任意合法下行 → 更新遥测/ACK → 下一轮 t0+120
         到 t0+117 无下行 → 失败计数+1 → 下一轮；连续 2 轮失败 → HANDSHAKE
NO_LINK/MISMATCH: 只发 HELLO，不发控制帧；UI 显示对应状态
```

**定拍规则**：本地 `esp_timer`，每轮 120ms，锚点是本轮 t0；迟到 >12ms 跳过该帧；迟到 >1 轮以当前时刻重新 t0；U0 AUX 忙最多等 2ms，仍失败整轮顺延。
