# 调试记录 2026-09-10（HC-SR04 测距读数不理想，软件侧优化）

## 现象
- `main_hsr.cpp` 里 HC-SR04 读数乱跳/偶尔离谱（忽大忽小、近处目标也报很远）。

## 根因（按影响从大到小）
1. **触发周期太快，没有安静期**：原代码"测到回波就立刻再触发"，近处目标一发只要 1~2ms。
   HC-SR04 数据手册要求两次测量间隔 ≥60ms，否则上一次的余振与多次反射还没停就发了下一发，
   回波互相串扰 —— 这是读数乱跳最常见的软件原因。
2. **没有"这一发的回波"归属判断**：超时（没回波）后，迟到的回波会被下一发当成自己的回波；
   多次反射的第二个回波也会被计数（容易出现正好 2 倍距离的读数）。
3. **没有有效窗口校验**：脉宽 0~65535µs 全部采纳，余振造成的几十µs 假脉冲也当成有效距离。
4. **等待上限 > 计数器溢出周期**：等回波 100ms，而 TIM7（1MHz、ARR=0xFFFF）65.5ms 就回绕，
   60~100ms 之间的回波会"回绕成一个短数"，被当成一个很像真的近距读数。
5. **无滤波**：单次采样直接输出，超声波本身的毛刺（±几 mm~几 cm）全部传给上层。
6. **声速用固定 58µs/cm**：对应约 20°C，温度变化会带来 1~3% 的系统性偏差（30°C 约 57.3µs/cm）。

## 做法（全部在软件侧，硬件接线没动）
- 触发周期固定 **60ms**（`kPingPeriodMs`），用 `rt_tick_get()` 计时 + `rt_thread_mdelay` 让出 CPU。
- 中断里加状态机：`armed`（主循环触发前置位）+ `inPulse`（必须"先上升后下降"成对出现），
  下降沿算完宽度就把 `armed` 清掉 → 一发只认一个回波；主循环超时也清 `armed` →
  迟到的回波不会算到下一发。
- 有效窗口 **[150µs, 25000µs]**（约 2.6cm~4.3m），窗口外丢弃并计数。
- 等待上限 **40ms < 65.5ms 溢出周期**；ISR 里脉宽超过 40ms 的回波直接作废。
- 不再在 ISR 里清零计数器，改成记录上升/下降沿计数值做回绕安全差值，
  顺便输出"触发→回波"延迟 `dly` 用于诊断假回波。
- 距离换算按温度修正声速：`c = 331.3 + 0.606*T`（m/s），`距离 = 脉宽 * c / 2`。
- 输出侧 **中值滤波(窗口 5) + 跳变抑制**：单次大跳变(>40cm)先丢；连续 3 次大跳变
  认为是真实位移，清窗口重新跟（避免滤波器"粘"在旧值上）。
- 每发打印一行明细 + 每秒一行汇总（命中率/抖动范围），便于直接对比滤波前后。

## 怎么验证/调参
- 明细行：`us`(原始脉宽) `dly`(触发→回波延迟) `mm`(原始距离) `f`(滤波距离) `win` `sp`(窗口极差)。
- 汇总行：`1s ping=17 miss=0 bad=0 rej=0 min=.. max=..`；`miss+bad` 应该很小，
  `min/max` 差 5~10mm 说明很稳，差几十 mm 说明环境反射复杂（或者该加大窗口/降触发频率）。
- `dly` 的作用：如果它稳定在几百µs（≈模块 8 周期 40kHz 突发时长），说明回波从突发结束才开始，
  脉宽就是往返时间；如果 `dly` 很小而读数整体偏大一个常数，就用 `kEchoOffsetUs` 减掉固定偏置。
- 用尺子卡一个已知距离（如 20cm）校准 `kEchoOffsetUs`。

## 软件修不了的（硬件侧排查清单）
- Echo 是 5V 电平：接 5V 耐受脚（本项目 PB1 属于 FT 脚）没问题，但别接到模拟脚。
- 供电/退耦：模块瞬时电流较大，VCC 就近加 100µF + 0.1µF，掉压会造成整批错数。
- 量程下限约 2cm；软质/斜面/细杆目标、强风、多径反射都会让读数变差。
- 多个超声波模块互相干扰：不同模块不要同时触发（软件上错开或加随机延迟）。
