# 调试记录 2026-09-09（TIM7 超声波 + BME280 I2C）

## BME280 I2C 读回 0x00/乱码（根因）
- 驱动 `writeReg` / `readRegs` 构造 `ByteBuffer` 后**未标记"已写入"**，`used()==0`。
- `IICDevice` 用 `buffer.used()` 发送，结果**寄存器地址一个字节都没发出去**。
- 现象：芯片在 0x76 正常应答（不卡死），但 ChipId 读回 0x00；校准未读，`calib` 为栈上随机值 → P/H/T 全乱码。
- 教训：设备能应答（不卡死）≠ 数据正确，先检查"寄存器选择字节是否真的发出"。
- 修复：`ByteBuffer w(buf,n); w.write(buf,n);` 显式标记 len，再交给 IIC。

## STM32 通用坑
- **写外设寄存器前必须先使能外设时钟**（`RCC_APB1PeriphClockCmd` 之后才能写 DIER/配置，否则写入被丢弃 → TIM7 更新中断不触发）。
- **RT-Thread 裸中断里严禁调用 RT-Thread API**：本工程 `stm32f4xx_it.cpp` 的 ISR 都是裸调 `DLX_IT_invoke_callback`，未包 `rt_interrupt_enter/leave`。从中断调 `rt_sem_release→rt_schedule` 会在中断上下文直接做线程切换 → 硬故障。改为只置普通 `volatile` 标志位，主循环有界轮询。
- **高频外设中断会拖垮 RT-Thread**：测时序尽量用自由运行计数器直接读 CNT，别用每 10µs 一次的更新中断。

## 快速判断
- 直读 ChipId(0xD0)：`0x60`=BME280，`0x58`=BMP280；其他值说明未真正读到该寄存器。
- "拔掉传感器是否卡死"：卡死=无设备；应答但数据不对=设备在/寄存器选择层问题。
